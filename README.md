# APCB Original Synchronizer

AtCoderの講義用特設コンテストで提出がACになったとき、その提出コードと言語を本家コンテストの対応問題へ引き継ぐChrome拡張機能です。

講義用特設コンテストで提出がACになると、本家の提出フォームへコードと言語を転記し、Turnstile認証が完了した後にネイティブフォームから提出します。人間による認証操作が必要な場合は提出フォームを表示し、認証トークンが確認できるまで送信しません。

Chrome拡張機能として読み込める構成も同梱しています。

## 対応環境

- Google Chrome
- AtCoderへログイン済みのブラウザ

Chrome拡張機能として導入します。ユーザースクリプトマネージャーは不要です。

## Chrome拡張機能として導入する手順

### 1. リポジトリを用意する

1. このリポジトリをZIPでダウンロードして展開するか、Gitでクローンします。
2. 展開先に `manifest.json` と `background.js` があることを確認します。

### 2. Chromeに読み込む

1. Chromeで `chrome://extensions/` を開きます。
2. 右上の「デベロッパー モード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. `manifest.json` があるリポジトリのルートフォルダーを選択します。
5. 一覧に **APCB Original Synchronizer** が表示され、「有効」になっていることを確認します。

導入後はChromeの再起動や拡張機能の再読み込みが必要になる場合があります。

## 拡張機能の動作確認

1. `https://atcoder.jp/contests/` の講義用特設コンテストを開きます。
2. 提出詳細画面でステータスが `AC` になるのを確認します。
3. 画面右上に認証・受付状況が表示されることを確認します。
4. 認証操作が必要な場合は表示された本家提出フォームで認証を完了します。
5. 本家で新しい提出IDが確認されてから、判定状況が表示されることを確認します。

受付や判定結果を確認できなかった場合は、AtCoder側の提出一覧を確認してください。

## 更新方法

ソースを更新した場合：

1. `chrome://extensions/` を開きます。
2. **APCB Original Synchronizer** の更新アイコン、または「更新」ボタンを押します。
3. 対象のAtCoderページを再読み込みします。

## 必要な権限

- `storage`: 本家AC記録と引き継ぎデータを拡張機能内に保存
- `scripting`: 提出iframeのMAIN worldでAceエディターとtextareaへコードを設定
- `webNavigation`: 同じタブ内の提出iframeを特定してコード設定先に限定
- `host_permissions`: `https://atcoder.jp/contests/*` のページにスクリプトを実行

本拡張機能はAtCoder以外への情報送信やサーバーへの連続自動アクセスを行いません。

## 難易度表示

講義コンテストの問題一覧・個別問題・提出一覧では、AtCoder Problemsの問題モデルから難易度を取得して表示します。

- 難易度データはChromeストレージの `problem_models_cache` に保存されます。
- キャッシュは24時間ごとに更新されます。
- 取得元は `https://kenkoooo.com/atcoder/resources/problem-models.json` です。
- 難易度が未定義または実験的な問題は灰色として扱います。
- 円アイコンをマウスオーバーすると `Difficulty: ...` が表示されます。

## 使用方法

1. 講義用特設コンテスト（`apcb_exercise_*`）で通常通り提出します。
2. 提出詳細画面でステータスが `AC` になると、本家提出フォームが準備されます。
3. Cloudflareの認証操作が必要な場合は表示されたフォームで完了します。
4. 認証トークン確認後に本家へ提出され、受付と判定状況が通知されます。

本家提出の受付を確認できた場合のみ、その提出IDの判定を追跡します。

## 動作ルール

- 対象講義コンテストは、デフォルトでコンテストIDが `apcb_exercise_` で始まるものです。
- 本家問題URLはタスクIDの先頭アンダースコア前の部分から文字列変換で生成します。
- サーバーへの連続自動アクセスや連続自動提出は行いません。
- キュー項目は講義側の提出URLに紐づき、別タブのpendingデータで問題が入れ替わらないようにします。
- 本家への提出開始は全タブで直列化されます。同時に複数の講義側ACが発生した場合、先の受付確認後に次の提出を開始します。
- 同じ講義側提出を複数タブで開いても、キュー登録と本家提出は重複しません。
- 本家への提出を開始した引き継ぎは、ページを再読み込みしても自動で再提出しません。
- Cloudflare認証中に別タブへ移動した場合、認証が完了するまでは提出しません。
- 引き継ぎデータには10分の有効期限があります。

## 設定

スクリプト冒頭の `CONFIG` を変更できます。

```javascript
const CONFIG = Object.freeze({
  LECTURE_CONTEST_REGEX: /^apcb_exercise_/,
  PENDING_TRANSFER_TTL_MS: 10 * 60 * 1000,
  SUBMITTED_TASKS_KEY: "submitted_tasks",
  PENDING_TRANSFER_KEY: "pending_transfer"
});
```

講義コンテスト名の規則を変更する場合は、通常 `LECTURE_CONTEST_REGEX` だけを変更します。

## 記録の解除

特設コンテストの問題一覧または提出一覧では、本家AC記録済み問題に `[本家AC記録済]` バッジと `[解除]` ボタンが表示されます。

提出詳細画面でも、すでに記録済みの場合は `[本家AC記録済]` バッジと `[記録解除]` ボタンが表示されます。解除する際は確認ダイアログが表示されます。

すべての記録をまとめて削除する場合は、拡張機能のDevToolsで次を実行します。

```javascript
chrome.storage.local.remove(["submitted_tasks", "pending_transfer"]);
```

## よくあるトラブル

### 本家提出フォームが起動しない

- `chrome://extensions/` で **APCB Original Synchronizer** が有効になっているか確認します。
- 提出詳細URLが特設コンテストの範囲か確認します。
- スクリプトの「Check for updates」を行ってからブラウザを再読み込みします。

### コードが入力されない

- 本家提出フォームの初期化後、Aceと送信用textareaの値が一致したことを確認してから進みます。設定に失敗した場合は講義側の提出詳細ページを再読み込みしてください。
- 提出画面は通常1×1pxに縮小し、「個人認証中...」「本家で採点中...」などの状態だけを表示します。結果通知は数秒後に消えます。認証操作が必要な場合は、手動操作用に提出画面が表示されます。
- 個人認証中に別タブへ移動しても、認証トークンができるまでは提出しません。手動認証が必要な場合はAtCoderタブへ戻って認証を完了してください。
- 「採点中」は本家提出一覧で今回の新しい提出IDを確認できた後だけ表示します。90秒以内に確認できない場合は受付未確認として停止し、再読み込みによる自動再提出はしません。
- 拡張機能を再読み込みした場合は、既に開いているAtCoderページも再読み込みしてください。
- ブラウザのコンソールにエラーがないか確認し、ページを再読み込みします。

### 言語が一致しない

- 本家問題ページの言語選択肢と提出画面の表示名が完全一致またはプレフィックス一致するか確認します。
- 一致しない場合は、本家問題ページで言語を手動選択してください。

### 本家AC記録が残ってしまう

- `[本家AC記録済]` または `[記録解除]` ボタンから解除します。
- 必要に応じて保存中の `submitted_tasks` を削除します。
